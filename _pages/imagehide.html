Where this runs. All encoding and decoding executes inside your browser via ONNX Runtime Web. Your image is never uploaded — the model is fetched once from a CDN and runs entirely on-device, in a Web Worker. No server is involved in the inference path.

Speed in production. The timings above are browser inference — single-threaded WASM on mobile, WebGPU on desktop — which is the slowest path the same model would ever run on. The encoder is only 251 K parameters and is designed to run on-camera at capture time. On real production hardware the speedup is dramatic:

  • Phone NPU (Apple ANE / Snapdragon Hexagon, the actual deployment target): < 50 ms per 0.5 MP image — roughly 100–500× faster than the browser-WASM mobile timing you see here.
  • Server CPU, native ONNX Runtime with AVX-512 + multi-threading: 50–200 ms.
  • Server GPU, native ONNX Runtime with fp16: 5–20 ms.

The demo gives up most of that headroom on purpose: it's single-threaded (browser WASM can't use threads without server-side COOP/COEP headers, which GitHub Pages doesn't serve), fp32 instead of fp16, one image at a time instead of batched, and pays a JS↔WASM marshaling cost on every tensor crossing.
